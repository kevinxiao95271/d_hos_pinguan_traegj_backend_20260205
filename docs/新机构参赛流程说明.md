## 📊 现状分析

### 数据存储结构

#### 1. 核心表结构

| 表名 | 说明 | 主要字段 |
|------|------|---------|
| **`institutions`** | 机构信息表 | id, name, code, uscc, region, level |
| **`user_accounts`** | 用户账号表 | id, phone, name, title, role, **institution_id** |
| **`registrations`** | 报名项目表 | id, competition_id, **institution_id**, **applicant_id**, project_name, status |

#### 2. 关联关系

```
institutions (机构)
    ↓ (1对多)
    ├─→ user_accounts (用户/负责人)
    │       ↓ (1对多)
    │       └─→ registrations (报名项目)
    │
    └─→ registrations (报名项目)
```

**关键外键**:
- `user_accounts.institution_id` → `institutions.id` (用户所属机构)
- `registrations.institution_id` → `institutions.id` (项目所属机构)
- `registrations.applicant_id` → `user_accounts.id` (项目负责人)

## 🚀 新机构参赛完整流程

### 方案一：通过登录接口自动创建（推荐）⭐

#### 特点
- ✅ **最简单**：一步完成用户创建和机构关联
- ✅ **自动化**：系统自动处理用户创建或更新
- ✅ **灵活**：支持用户信息更新

#### 流程步骤

##### 1. 确保机构已存在
```sql
-- 查询机构ID
SELECT id, name, code FROM institutions WHERE name LIKE '%医院名称%';
```

如果机构不存在，需要先创建（见方案二）。

##### 2. 负责人登录/注册
```bash
POST /api/auth/login
Content-Type: application/json

{
  "phone": "13900000001",           # 必填：手机号（唯一标识）
  "name": "张三",                    # 必填：姓名
  "title": "护理部主任",             # 可选：职称
  "role": "CONTESTANT",              # 必填：角色（参赛者）
  "institutionId": 34                # 必填：机构ID
}
```

**返回结果**:
```json
{
  "code": 200,
  "data": {
    "id": 150,
    "phone": "13900000001",
    "name": "张三",
    "title": "护理部主任",
    "role": "CONTESTANT",
    "institutionId": 34,
    "institutionName": "杭州市临安区第三人民医院",
    "institutionCode": "INS-0034",
    "institutionUscc": "12330185470362268D",
    "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9..."
  }
}
```

##### 3. 创建报名项目
```bash
POST /api/registrations
Authorization: Bearer {token}
Content-Type: application/json

{
  "competitionId": 1,                # 赛事ID
  "institutionId": 34,               # 机构ID
  "applicantId": 150,                # 负责人ID（从登录返回获取）
  "projectName": "提升患者满意度项目",
  "groupType": "GRASSROOTS"          # 竞赛组别
}
```

### 方案二：通过数据库直接维护（OPS角色）

#### 特点
- ✅ **批量操作**：适合批量导入多个机构和用户
- ✅ **完全控制**：可精确控制所有字段
- ⚠️ **需要权限**：仅限OPS角色操作

#### 流程步骤

##### 1. 添加机构（如果不存在）
```sql
-- 检查机构是否存在
SELECT * FROM institutions WHERE uscc = '12330185470362268D';

-- 如果不存在，插入新机构
INSERT INTO institutions (name, code, uscc, region, level, created_at)
VALUES (
  '杭州市临安区第三人民医院',
  'INS-0034',
  '12330185470362268D',
  '杭州',
  '三级乙等',
  NOW()
);

-- 获取机构ID
SELECT id FROM institutions WHERE uscc = '12330185470362268D';
-- 假设返回 id = 34
```

##### 2. 添加项目负责人
```sql
-- 检查用户是否存在
SELECT * FROM user_accounts WHERE phone = '13900000001';

-- 如果不存在，插入新用户
INSERT INTO user_accounts (phone, name, title, role, institution_id, created_at)
VALUES (
  '13900000001',
  '张三',
  '护理部主任',
  'CONTESTANT',
  34,  -- 机构ID
  NOW()
);

-- 获取用户ID
SELECT id FROM user_accounts WHERE phone = '13900000001';
-- 假设返回 id = 150
```

##### 3. 创建报名项目（可选，也可由负责人自己创建）
```sql
INSERT INTO registrations (
  competition_id,
  institution_id,
  applicant_id,
  project_name,
  group_type,
  status,
  created_at
)
VALUES (
  1,                              -- 赛事ID
  34,                             -- 机构ID
  150,                            -- 负责人ID
  '提升患者满意度项目',
  'GRASSROOTS',                   -- 竞赛组别
  'DRAFT',                        -- 初始状态：草稿
  NOW()
);
```

## ⚠️ 重要约束和规则

### 1. 唯一性约束
- ✅ `institutions.code` 必须唯一（机构代码）
- ✅ `institutions.uscc` 必须唯一（统一社会信用代码）
- ✅ `user_accounts.phone` 必须唯一（手机号）

### 2. 外键约束
- ✅ `user_accounts.institution_id` 必须存在于 `institutions.id`
- ✅ `registrations.institution_id` 必须存在于 `institutions.id`
- ✅ `registrations.applicant_id` 必须存在于 `user_accounts.id`

### 3. 数据一致性规则
- ✅ **报名项目的机构ID 必须等于 负责人的机构ID**
- ✅ 负责人的角色必须是 `CONTESTANT`
- ✅ 一个机构可以有多个负责人
- ✅ 一个负责人可以创建多个报名项目

## 📞 常见问题

### Q1: 新机构如何参赛？
**A**: 有两种方式：
1. **推荐方式**：负责人通过 `/api/auth/login` 接口登录时，提供 `institutionId`，系统自动创建用户并关联机构。
2. **数据库方式**：OPS角色直接在数据库中插入用户记录，设置 `institution_id`。

### Q2: 机构不存在怎么办？
**A**: 需要先创建机构：
- **方式1**：OPS角色通过 `/api/institutions` 接口创建
- **方式2**：OPS角色直接在数据库中插入机构记录

### Q3: 一个机构可以有多个负责人吗？
**A**: 可以！一个机构可以有多个用户（`user_accounts.institution_id` 相同），每个用户都可以创建自己的报名项目。

### Q4: 负责人可以更换机构吗？
**A**: 可以，但需要注意：
- 更新 `user_accounts.institution_id` 即可
- 但已创建的报名项目的 `registrations.institution_id` 不会自动更新
- 建议：如果负责人更换机构，应该创建新的报名项目

### Q5: 报名项目的机构和负责人的机构不一致会怎样？
**A**: 系统目前允许这种情况，但不推荐。建议保持一致性：
- `registrations.institution_id` = `user_accounts.institution_id`

### Q6: 目前有接口可以批量导入机构和负责人吗？
**A**: 目前没有。建议：
- **临时方案**：使用数据库脚本批量导入
- **长期方案**：开发 `/api/admin/institutions/import-with-users` 接口
