#### 2. 激活机构（复制数据）

**文件**: `ConstInitInstitutionService.java`

```java
/**
 * 激活机构：从 const_init_institutions 同步到 institutions
 * 用于用户注册时选择机构
 * 
 * @param constInstitutionId const_init_institutions 表的ID
 * @return 同步后的 Institution ID
 */
@Transactional
public Long activateInstitution(Long constInstitutionId) {
    // 1. 从 const_init_institutions 查询
    ConstInitInstitution constInst = constInitInstitutionRepository
            .findById(constInstitutionId)
            .orElseThrow(() -> new IllegalArgumentException("机构不存在"));
    
    // 2. 检查 institutions 表中是否已存在（按 USCC）
    Institution existing = institutionRepository
            .findByUscc(constInst.getUscc())
            .orElse(null);
    
    if (existing != null) {
        // 已存在，直接返回
        return existing.getId();
    }
    
    // 3. 复制数据到 institutions 表
    Institution newInst = constInst.toInstitution();  // ⬅️ 转换方法
    newInst = institutionRepository.save(newInst);
    
    // 4. 返回 institutions 表的 ID
    return newInst.getId();
}
```

**转换方法** (`ConstInitInstitution.java`):

```java
/**
 * 转换为 Institution 实体（用于同步）
 */
public Institution toInstitution() {
    return Institution.builder()
            .code(this.code)
            .uscc(this.uscc)
            .name(this.name)
            .region(this.region)
            .level(this.level)
            .createdAt(LocalDateTime.now())
            .build();
}
```

**说明**:
- ✅ 按 USCC 去重，避免重复复制
- ✅ 只在首次使用时复制数据
- ✅ 返回的是 `institutions.id`，不是 `const_init_institutions.id`

## 🔍 架构优势

### 优势1: 性能隔离

**问题**（如果直接关联 const_init_institutions）:
```sql
-- ❌ 不推荐：直接关联 42K+ 数据
SELECT r.*, ci.name, ci.level
FROM registrations r
JOIN const_init_institutions ci ON r.const_institution_id = ci.id
WHERE r.competition_id = 1;
```

- ❌ JOIN 42K+ 的大表，性能差
- ❌ 索引压力大
- ❌ 查询缓存命中率低

**解决方案**（当前实现）:
```sql
-- ✅ 推荐：关联小表
SELECT r.*, i.name, i.level
FROM registrations r
JOIN institutions i ON r.institution_id = i.id
WHERE r.competition_id = 1;
```

- ✅ JOIN 100+ 的小表，性能好
- ✅ 索引高效
- ✅ 查询速度快

---

### 优势2: 数据独立性

**const_init_institutions** 的变化不影响业务:
- 可以随时更新、补充机构数据
- 可以重新导入
- 不影响已注册用户和已创建的报名

**institutions** 的数据稳定:
- 数据一旦复制，就是稳定的业务数据
- 不受 const_init_institutions 变化影响

---

### 优势3: 去重控制

**按 USCC 自动去重**:
```java
// 检查是否已经激活（在 institutions 表中存在）

if (existing != null) {
    return existing.getId();  // ⬅️ 返回已有记录
}
```

**好处**:
- ✅ 多个用户选择同一机构 → 只创建一条 institutions 记录
- ✅ institutions 表数据量更小
- ✅ 避免冗余
