# 机构表权限说明

## 🔐 权限概述

### 系统角色定义

系统共有 **5个角色**，定义在 `RoleType` 枚举中：

```java
public enum RoleType {
    CONTESTANT,        // 参赛者（报名、提交项目）
    REVIEWER,          // 评审专家（书审、面试、决赛评审）
    COMMITTEE,         // 组委会（任务分配、结果查看）
    COMMITTEE_ADMIN,   // 组委会管理员
    OPS                // 系统运维（系统配置、数据管理）★
}
```

---

## 📋 机构表 (institutions) 权限分配

### ✅ OPS 角色（系统运维）- **完整权限**

**运维角色拥有机构表的全部权限**，包括：

#### 1. 查看权限 ✅
- ✅ 查看所有机构列表
- ✅ 查看机构详细信息
- ✅ 导出机构数据（含未填地区筛选）

#### 2. 修改权限 ✅
- ✅ 创建新机构
- ✅ 更新机构信息（名称、代码、USCC、地区）
- ✅ 单独更新机构地区
- ✅ 删除机构

#### 3. 批量操作权限 ✅
- ✅ 批量导入机构（预检）
- ✅ 批量导入机构（确认落库）

---

### ⚠️ 其他角色 - **只读权限**

**CONTESTANT、REVIEWER、COMMITTEE、COMMITTEE_ADMIN** 这4个角色对机构表只有**只读权限**：

#### 可以做的操作 ✅
- ✅ 查看机构列表
- ✅ 查看机构详情

#### 不能做的操作 ❌
- ❌ 创建新机构
- ❌ 更新机构信息
- ❌ 删除机构
- ❌ 批量导入机构
- ❌ 导出机构数据

## 🔌 API接口权限详解

### 1. 普通机构接口 (`/api/institutions`)

**权限要求**: 所有登录用户（任何角色）

| 接口 | 方法 | 说明 | OPS | 其他角色 |
|------|------|------|-----|---------|
| `/api/institutions` | GET | 机构列表 | ✅ | ✅ |
| `/api/institutions/{id}` | GET | 机构详情 | ✅ | ✅ |
| `/api/institutions` | POST | 新增机构 | ✅ | ⚠️ 可调用但不推荐 |
| `/api/institutions/{id}` | PUT | 更新机构 | ✅ | ⚠️ 可调用但不推荐 |
| `/api/institutions/{id}` | DELETE | 删除机构 | ✅ | ⚠️ 可调用但不推荐 |
| `/api/institutions/import` | POST | 批量导入 | ✅ | ⚠️ 可调用但不推荐 |

> ⚠️ **注意**: 普通接口虽然技术上所有角色都可调用，但**建议只有OPS角色使用修改类接口**，其他角色只使用查询接口。

---

### 2. 后台机构接口 (`/api/admin/institutions`) ⭐

**权限要求**: **仅限 OPS 角色**

| 接口 | 方法 | 说明 | OPS | 其他角色 |
|------|------|------|-----|---------|
| `/api/admin/institutions/export` | GET | 导出机构列表 | ✅ | ❌ 403 Forbidden |
| `/api/admin/institutions/import/precheck` | POST | 导入预检（不落库） | ✅ | ❌ 403 Forbidden |
| `/api/admin/institutions/import/confirm` | POST | 导入确认（落库） | ✅ | ❌ 403 Forbidden |
| `/api/admin/institutions/{id}/region` | PUT | 更新机构地区 | ✅ | ❌ 403 Forbidden |

#### 权限检查代码
```java
private void requireOpsRole() {
    Object roleObj = request.getAttribute("role");
    String role = roleObj == null ? null : roleObj.toString();
    if (!"OPS".equals(role)) {
        throw new ResponseStatusException(HttpStatus.FORBIDDEN, "无权限");
    }
}
```

## 📊 实际操作示例

### 场景1: OPS角色查看并修改机构

```bash

POST /api/admin/institutions/import/precheck
Headers: Authorization: Bearer eyJhbGc...
```

## 🛠️ 管理工具使用指南

### 对于 OPS 角色

#### 1. 查看所有机构
```bash
GET http://localhost:6031/api/institutions
Authorization: Bearer {your_token}
```

#### 2. 导出未填地区的机构
```bash
GET http://localhost:6031/api/admin/institutions/export?unknownRegionOnly=true
Authorization: Bearer {your_token}
```

#### 3. 批量更新机构地区
```bash
# 步骤1: 导出未填地区的机构
GET /api/admin/institutions/export?unknownRegionOnly=true

# 步骤2: 准备导入数据（Excel或JSON）
{
  "items": [
    {"name": "浙江大学医学院附属第一医院", "code": "INS-0001", "uscc": "1233000047053349XG", "region": "杭州"},
    {"name": "浙江大学医学院附属第二医院", "code": "INS-0002", "uscc": "1233000047053325XJ", "region": "杭州"}
  ]
}

# 步骤3: 预检（不落库）
POST /api/admin/institutions/import/precheck
Body: {上述JSON数据}

# 步骤4: 确认导入（落库）
POST /api/admin/institutions/import/confirm
Body: {上述JSON数据}
```

#### 4. 单独更新某个机构的地区
```bash
PUT http://localhost:6031/api/admin/institutions/1/region?region=杭州
Authorization: Bearer {your_token}
```

#### 5. 删除机构（谨慎操作）
```bash
# 注意：删除前请确认没有关联数据（用户、报名）
DELETE http://localhost:6031/api/institutions/5
Authorization: Bearer {your_token}
```

## 🔍 数据库直接操作

### OPS角色可以直接操作数据库

如果需要批量修改或复杂查询，OPS角色可以直接连接数据库：

```sql
-- 连接信息
-- 主机: gz-cdb-bq7gk3k5.sql.tencentcdb.com:63606
-- 数据库: d_hos_pinguan_traegj_20260205
-- 用户: root
-- 密码: Yiguo9527_

-- 查看所有机构
SELECT * FROM institutions ORDER BY id;

-- 查看未填地区的机构
SELECT * FROM institutions WHERE region IS NULL OR region = '';

-- 批量更新地区（示例：根据机构名称匹配）
UPDATE institutions SET region = '杭州' WHERE name LIKE '%杭州%';
UPDATE institutions SET region = '宁波' WHERE name LIKE '%宁波%';
UPDATE institutions SET region = '温州' WHERE name LIKE '%温州%';

-- 更新单个机构的地区
UPDATE institutions SET region = '杭州' WHERE id = 1;

-- 删除测试机构（谨慎操作）
DELETE FROM institutions WHERE id = 999;

-- 统计各地区机构数量
SELECT region, COUNT(*) as count 
FROM institutions 
GROUP BY region 
ORDER BY count DESC;
```

## ⚠️ 安全建议

### 1. 角色分配
- ✅ **OPS角色应该只分配给系统管理员**
- ⚠️ 不要给普通用户分配OPS角色
- ⚠️ 组委会成员应使用COMMITTEE或COMMITTEE_ADMIN角色

### 2. 数据操作
- ✅ 修改机构信息前请先备份数据
- ✅ 删除机构前请检查关联数据（用户、报名）
- ✅ 批量导入前请使用预检接口验证数据
- ⚠️ 不要直接在生产环境执行DELETE语句

### 3. 敏感信息
- ⚠️ 统一社会信用代码(USCC)是敏感信息
- ✅ 对外API建议只暴露机构ID和名称
- ✅ 日志中不要记录完整的USCC

## 🎯 快速答案

### Q1: 系统运维角色能看到机构表吗？
**A: ✅ 能！OPS角色拥有机构表的完整读取权限。**

### Q2: 系统运维角色能修改维护字段信息吗？
**A: ✅ 能！OPS角色拥有机构表的完整修改权限，包括：**
- 创建新机构
- 更新机构名称、代码、统一社会信用代码、地区
- 删除机构
- 批量导入/导出机构数据
- 直接操作数据库

### Q3: 其他角色能修改机构信息吗？
**A: ⚠️ 技术上可以调用普通接口（/api/institutions）进行修改，但：**
- 不能调用后台接口（/api/admin/institutions）
- 不推荐其他角色进行修改操作
- 建议统一由OPS角色管理机构数据
