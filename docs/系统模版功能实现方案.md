# 系统模版文件管理功能实现方案

## 一、需求概述

### 当前情况
根目录下有两个 Word 文档模版文件：
1. `2026浙江省医院品管大赛报名表模板.docx` (约17KB)
2. `成果报告相关说明.docx` (约18KB)

### 业务需求
1. **OPS 运维人员**：可以上传、更新、管理这些模版文件
2. **CONTESTANT 注册用户**：在注册流程的最后一步可以下载这些模版文件

## 二、技术方案设计

### 2.1 数据库设计

#### 新增表：`system_template_files`

```sql
CREATE TABLE system_template_files (
    id BIGINT AUTO_INCREMENT PRIMARY KEY COMMENT '主键ID',
    template_type VARCHAR(64) NOT NULL COMMENT '模版类型: registration_form(报名表), result_report(成果报告)',
    file_name VARCHAR(200) NOT NULL COMMENT '原始文件名',
    file_path VARCHAR(300) NOT NULL COMMENT '文件存储路径',
    file_size BIGINT NOT NULL COMMENT '文件大小(字节)',
    version INT NOT NULL DEFAULT 1 COMMENT '版本号',
    is_active BOOLEAN NOT NULL DEFAULT TRUE COMMENT '是否当前激活版本',
    uploaded_by BIGINT COMMENT '上传人用户ID',
    uploaded_at DATETIME NOT NULL COMMENT '上传时间',
    description VARCHAR(500) COMMENT '描述信息',
    
    CONSTRAINT fk_uploaded_by FOREIGN KEY (uploaded_by) REFERENCES user_accounts(id),
    INDEX idx_template_type (template_type),
    INDEX idx_is_active (is_active),
    INDEX idx_type_active (template_type, is_active)
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4 COMMENT='系统模版文件表';
```

**字段说明：**
- `template_type`：枚举类型，固定为 `registration_form` 或 `result_report`
- `is_active`：每种类型同时只有一个激活版本（供用户下载），历史版本保留但不激活
- `version`：版本号，每次上传新模版时自动递增

### 2.2 文件存储目录结构

```
data/
  └── system-templates/
      ├── registration_form/
      │   ├── {UUID}-2026浙江省医院品管大赛报名表模板.docx

          └── {UUID}-成果报告相关说明.docx
```

**存储策略：**
- 文件名格式：`{UUID}-{原始文件名}`
- 按 `template_type` 分类存储
- 使用 UUID 前缀避免文件名冲突

```java
// 新增方法
public String storeSystemTemplate(String templateType, MultipartFile file) {
    try {
        Path targetDir = Paths.get("data", "system-templates", templateType);
        Files.createDirectories(targetDir);
        String filename = UUID.randomUUID() + "-" + file.getOriginalFilename();
        Path targetFile = targetDir.resolve(filename);
        Files.copy(file.getInputStream(), targetFile);
        return targetFile.toAbsolutePath().toString();
    } catch (IOException ex) {
        throw new IllegalStateException("系统模版文件保存失败");
    }
}
```

## 五、核心业务逻辑

### 5.1 上传新模版流程

```
1. OPS 上传新模版文件 (MultipartFile)
2. 校验文件格式（仅允许 .docx, .doc, .pdf 等）
3. 使用 FileStorageService 存储文件到 data/system-templates/{type}/
4. 查询该类型当前的最大版本号 (maxVersion)
5. 将该类型的所有激活模版设为 is_active=false
6. 创建新记录：
   - version = maxVersion + 1
   - is_active = true
   - file_path = 存储路径
7. 返回成功响应
```

**关键代码逻辑：**
```java
@Transactional
public SystemTemplateFile uploadTemplate(SystemTemplateType type, MultipartFile file, 
                                         Long uploaderId, String description) {
    // 1. 获取当前最大版本号
    Integer maxVersion = repository.findMaxVersionByType(type.getCode());
    int newVersion = (maxVersion == null) ? 1 : maxVersion + 1;
    
    // 2. 停用该类型的旧版本
    repository.deactivateByType(type.getCode());
    
    // 3. 存储文件
    String filePath = fileStorageService.storeSystemTemplate(type.getCode(), file);
    
    // 4. 创建新记录
    SystemTemplateFile template = SystemTemplateFile.builder()
        .templateType(type.getCode())
        .fileName(file.getOriginalFilename())
        .filePath(filePath)
        .fileSize(file.getSize())
        .version(newVersion)
        .isActive(true)
        .uploadedBy(uploaderId)
        .uploadedAt(LocalDateTime.now())
        .description(description)
        .build();
    
    return repository.save(template);
}
```

### 5.2 用户下载模版流程

```
1. 前端调用 GET /api/system-templates/active 获取所有激活模版列表
2. 展示模版列表（报名表模版、成果报告说明）
3. 用户点击下载按钮
4. 前端调用 GET /api/system-templates/{id}/download
5. 后端根据 ID 查询模版记录，读取 file_path
6. 以文件流形式返回给前端（Content-Disposition: attachment）
7. 前端触发浏览器下载
```

**关键代码：**
```java
@GetMapping("/{id}/download")
public ResponseEntity<Resource> download(@PathVariable Long id) {
    SystemTemplateFile template = service.getById(id);
    Resource resource = new FileSystemResource(Paths.get(template.getFilePath()));
    
    return ResponseEntity.ok()
        .contentType(MediaType.APPLICATION_OCTET_STREAM)
        .header(HttpHeaders.CONTENT_DISPOSITION, 
                "attachment; filename=\"" + template.getFileName() + "\"")
        .body(resource);
}
```

## 六、数据初始化

### 6.1 初始化脚本逻辑

**`scripts/init_system_templates.py`** 伪代码：

```python
import shutil
import pymysql
from pathlib import Path

# 1. 连接数据库
conn = pymysql.connect(...)

# 2. 创建目录
Path("data/system-templates/registration_form").mkdir(parents=True, exist_ok=True)
Path("data/system-templates/result_report").mkdir(parents=True, exist_ok=True)

# 3. 移动文件并生成 UUID
files = [
    {
        "source": "2026浙江省医院品管大赛报名表模板.docx",
        "type": "registration_form"
    },
    {
        "source": "成果报告相关说明.docx",
        "type": "result_report"
    }
]

for file_info in files:
    uuid = str(uuid4())
    src = Path(file_info["source"])
    dst = Path(f"data/system-templates/{file_info['type']}/{uuid}-{src.name}")
    
    # 移动文件
    shutil.move(str(src), str(dst))
    
    # 插入数据库记录
    sql = """
    INSERT INTO system_template_files 
    (template_type, file_name, file_path, file_size, version, is_active, uploaded_at)
    VALUES (%s, %s, %s, %s, 1, TRUE, NOW())
    """
    cursor.execute(sql, (
        file_info["type"],
        src.name,
        str(dst.absolute()),
        dst.stat().st_size
    ))

conn.commit()
```

## 十、风险和注意事项

### 10.1 安全性
- ✅ 上传文件类型校验（仅允许 .docx, .doc, .pdf）
- ✅ 文件大小限制（application.yml 中已配置 30MB）
- ✅ OPS 权限严格校验

### 10.2 性能
- ✅ 文件存储在本地文件系统，下载速度快
- ✅ 使用索引优化查询（`idx_template_type`, `idx_is_active`）

### 10.3 数据一致性
- ✅ 使用 `@Transactional` 确保上传操作的原子性
- ✅ 删除模版时同步删除物理文件

### 10.4 兼容性
- ⚠️ 需要确保 `data/system-templates/` 目录有读写权限
- ⚠️ 如果部署在多台服务器，需要共享文件存储（如 NFS）

## 十二、总结

1. **提升用户体验**：注册完成后立即可下载所需模版，流程顺畅
