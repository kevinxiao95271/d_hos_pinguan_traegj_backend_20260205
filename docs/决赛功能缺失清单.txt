【缺失功能清单】❌
================================================================================

一、决赛分组功能（4个API）

  1. GET /api/admin/finals/pending-projects
     功能: 获取待分组项目（面谈入围的项目）
     优先级: P0（必须）

  2. POST /api/admin/finals/auto-group
     功能: 按规则自动分组（按组别/分数段/区域）
     优先级: P0（必须）

  3. GET /api/admin/finals/groups
     功能: 获取决赛分组列表
     优先级: P0（必须）

  4. PUT /api/admin/registrations/{id}/final-group
     功能: 手动调整项目的决赛分组
     优先级: P1（重要）

  数据表扩展:
    registrations表需新增字段:
      - final_group_code VARCHAR(64)
      - final_group_name VARCHAR(128)

--------------------------------------------------------------------------------

二、专家分配功能（2个API）

  5. POST /api/admin/reviews/assign-final-tasks
     功能: 为决赛分组批量分配评委
     优先级: P0（必须）

  6. POST /api/admin/reviews/smart-assign-final
     功能: 智能分配（考虑专家背景、机构等）
     优先级: P2（可选）

--------------------------------------------------------------------------------

三、扫码打分功能（3个API + 1个表）

  7. GET /api/reviews/tasks/{taskId}/qrcode
     功能: 生成打分二维码
     优先级: P2（可选）

  8. GET /api/reviews/scan/{token}
     功能: 扫码后获取任务信息
     优先级: P2（可选）

  9. GET /api/admin/finals/scoring-status
     功能: 实时获取决赛现场打分进度
     优先级: P1（重要）

  新增数据表: qrcode_tokens
    字段: id, token, task_id, reviewer_id, expire_at, used, created_at

  说明: 扫码功能是加分项，不影响核心流程
        现有打分API已支持决赛，评委可直接登录打分

--------------------------------------------------------------------------------

四、结果汇总功能（5个API + 2个表）

  10. GET /api/admin/results/comprehensive
      功能: 获取综合成绩排名（书审+面谈+决赛）
      优先级: P0（必须）
      
      说明: 现有rankings API只支持单阶段，需要新API支持三阶段汇总

  11. POST /api/admin/results/award-rules
      功能: 设置奖项规则（按比例或按分数段）
      优先级: P1（重要）

  12. POST /api/admin/results/generate-awards
      功能: 根据规则生成获奖名单
      优先级: P1（重要）

  13. GET /api/admin/results/awards
      功能: 获取获奖名单
      优先级: P1（重要）

  14. GET /api/admin/results/awards/export
      功能: 导出获奖名单（Excel/PDF）
      优先级: P2（可选）

  新增数据表1: award_rules（奖项规则）
    字段: id, competition_id, rule_type, award_level, award_name, 
          percentage, min_score, created_at

  新增数据表2: award_results（获奖结果）
    字段: id, competition_id, registration_id, award_level, award_name,
          comprehensive_score, book_score, interview_score, final_score,
          rank_overall, rank_in_group, created_at

================================================================================
【核心业务流程】
================================================================================

1. 决赛分组（组委会）
   → 获取待分组项目（API 1）
   → 自动分组或手动分组（API 2, 4）
   → 查看分组结果（API 3）

2. 专家分配（组委会）
   → 选择决赛分组
   → 批量分配评委（API 5）
   → 确认分配结果

3. 现场打分（评委）
   → 登录系统或扫码
   → 查看我的任务（已有）
   → 提交决赛评分（已有）

4. 结果汇总（组委会）
   → 查看综合成绩排名（API 10）
   → 设置奖项规则（API 11）
   → 生成获奖名单（API 12）
   → 查看/导出获奖名单（API 13, 14）

================================================================================
【技术决策建议】
================================================================================

扫码打分实现:
  推荐: Token-based方案
  - 生成短期有效token（30分钟）
  - 存储在qrcode_tokens表
  - 简单、可控

实时打分监控:
  推荐: 轮询（Polling）
  - 前端每5-10秒请求一次
  - 简单、符合现有架构
  - 后期可升级WebSocket

综合成绩计算:
  位置: RegistrationService
  - 支持自定义权重
  - 缓存计算结果（如需）
