# 项目负责人跨大类报名分析

## 分析目标

分析历史数据中，同一个项目负责人提交多个项目时，是否跨基层组/综合组/进阶组报名。

## 数据概况

- 数据年度: 2024年、2025年
- 总记录数: 1818条
- 提交多个项目的负责人: 28人

## 分析结论

### 1. 主要特征

✅ **绝大多数负责人（78.6%）的多个项目集中在同一大类**

这说明：
- 负责人通常在自己熟悉的领域深耕
- 项目之间有一定的关联性和延续性
- 大类选择相对稳定

### 2. 跨大类特征

⚠️ **少数负责人（21.4%）会跨大类报名，且都是"综合组+进阶组"**

这说明：
- 跨大类主要发生在综合组和进阶组之间
- 基层组相对独立，不与其他大类混合
- 跨大类的负责人通常来自较大的医院，有能力同时开展不同难度的项目

### 3. 对自动分组算法的建议

基于历史数据分析，建议自动分组算法采用以下策略：

#### 策略1: 优先保持同一大类（推荐）

**适用场景**: 78.6%的情况

```
如果同一负责人有多个项目：
  1. 优先将所有项目分配到同一大类的不同细分组
  2. 例如：综合组的项目分配到B1、B2、B3等
```

**优点**:
- 符合大多数历史数据特征
- 项目之间有关联性，便于评审
- 负责人在同一赛道竞争

#### 策略2: 允许跨大类分配（次选）

**适用场景**: 21.4%的情况

```
如果同一大类的细分组容量不足：
  1. 允许跨大类分配
  2. 优先选择"综合组+进阶组"的组合
  3. 避免涉及基层组的跨大类分配
```

**约束条件**:
- 跨大类占比应控制在20-25%以内
- 优先考虑综合组和进阶组之间的跨越
- 基层组保持独立性

#### 策略3: 分组容量平衡

```
在满足上述策略的前提下：
  1. 保持各细分组的项目数量平衡
  2. 避免某个细分组过度集中
  3. 标准差控制在2.5以内
```
