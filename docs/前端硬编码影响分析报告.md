# 前端硬编码影响分析报告

## 📌 问题概述

前端硬编码了两个 code 值来判断是否显示"其他"文本输入框：
- `'other'`
- `'subject_type_11'`

但数据库中4个字典类型的"其他"选项**标准不统一**。

---

## 🔍 当前数据库实际情况

| 字典类型 | "其他"选项的 code | 使用次数 | 是否被前端硬编码 |
|---------|------------------|---------|----------------|
| **主题类型** (subject_type) | `subject_type_11` | 6次 | ✅ 是 |
| **运用手法** (method) | `method_16` | 5次 | ❌ **否** |
| **改善就医感受** (experience_improve) | `other` | 15次 | ✅ 是 |
| **医疗质量安全主题** (quality_topic) | `other` | 9次 | ✅ 是 |

---

## ⚠️ 问题分析

### 问题1: 标准不统一

4个字典类型使用了3种不同的 code：
- `subject_type_11`
- `method_16`
- `other`

### 问题2: 前端硬编码不完整

前端只硬编码了 `'other'` 和 `'subject_type_11'`，但**没有硬编码 `'method_16'`**。

**影响**：
- 如果前端代码是这样：
  ```javascript
  if (code === 'other' || code === 'subject_type_11') {
    showOtherInput = true;
  }
  ```
- 那么 **`method` 类型的"其他"选项将无法触发文本输入框显示** ❌

### 问题3: 与字典清理方案的关系

在之前的"字典重复数据清理方案"中：
- ✅ **未涉及** `subject_type_11`、`method_16`、`other`
- ✅ 这些 code 没有重复的 label
- ✅ 不会被删除

但清理方案**没有解决标准不统一的问题**。

---

## 💡 解决方案

### 🎯 方案A：统一使用 'other' code（推荐）

#### 优点
- ✅ 标准统一，易于维护
- ✅ 前端只需要一个硬编码：`if (code === 'other')`
- ✅ 符合语义化命名规范

#### 执行步骤

##### Step 1: 在 subject_type 中创建 'other' code

```sql
-- 检查 subject_type 是否已有 'other' code
SELECT * FROM dictionary_items WHERE type = 'subject_type' AND code = 'other';

-- 如果不存在，创建 'other' code（复制 subject_type_11 的 label）
INSERT INTO dictionary_items (type, code, label, active)
SELECT 'subject_type', 'other', label, active
FROM dictionary_items
WHERE type = 'subject_type' AND code = 'subject_type_11';
```

##### Step 2: 在 method 中创建 'other' code

```sql
-- 检查 method 是否已有 'other' code
SELECT * FROM dictionary_items WHERE type = 'method' AND code = 'other';

-- 如果不存在，创建 'other' code（复制 method_16 的 label）
INSERT INTO dictionary_items (type, code, label, active)
SELECT 'method', 'other', label, active
FROM dictionary_items
WHERE type = 'method' AND code = 'method_16';
```

##### Step 3: 数据迁移

```sql
-- 迁移 subject_type 的数据 (6条记录)
UPDATE activity_infos 
SET subject_type_code = 'other' 
WHERE subject_type_code = 'subject_type_11';

-- 迁移 method 的数据 (5条记录)
UPDATE activity_infos 
SET method_code = 'other' 
WHERE method_code = 'method_16';
```

##### Step 4: 删除旧 code

```sql
-- 删除旧的 subject_type_11
DELETE FROM dictionary_items WHERE type = 'subject_type' AND code = 'subject_type_11';

-- 删除旧的 method_16
DELETE FROM dictionary_items WHERE type = 'method' AND code = 'method_16';
```

##### Step 5: 验证

```sql
-- 验证所有类型都使用 'other'
SELECT type, code, label 
FROM dictionary_items 
WHERE label LIKE '%其他%'
ORDER BY type;

-- 预期结果：4行，都是 code='other'
```

#### 前端调整

**修改前**：
```javascript
// 旧的硬编码
if (code === 'other' || code === 'subject_type_11') {
  showOtherInput = true;
}
```

**修改后**：
```javascript
// 统一使用 'other'
if (code === 'other') {
  showOtherInput = true;
}
```

✅ **更简洁、更统一**

---

### 方案B：保持现状，前端补全硬编码（不推荐）

#### 前端调整

```javascript
// 补全所有硬编码
if (code === 'other' || code === 'subject_type_11' || code === 'method_16') {
  showOtherInput = true;
}
```

#### 缺点
- ❌ 标准不统一
- ❌ 前端需要维护多个硬编码
- ❌ 未来如果有新的字典类型，可能又是新的 code
- ❌ 不符合规范
