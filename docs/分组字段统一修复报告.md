# 分组列表字段统一修复报告

## 问题描述

**现象：**
- 书审分组页面：点击详情正常
- 面谈分组页面：点击详情没有反应

**根因分析：**
后端API返回的列表数据中，关键字段（报名ID）的命名不统一，导致前端在不同页面使用不同字段名时，部分页面无法正确获取ID值。

## 问题定位

### 1. API对比

| API | 返回DTO | 原字段 | 问题 |
|-----|---------|--------|------|
| `/api/admin/registrations/filter` | `RegistrationFilterItem` | 只有 `registrationId` | 书审页面正常，说明前端用的是 `registrationId` |
| `/api/admin/registrations/interview-groups` | `GroupedRegistrationItem` | 只有 `registrationId` | 面谈页面不正常，前端可能期望 `id` 字段 |

### 2. 其他DTO对比

检查项目中其他类似的列表DTO：

```java
// MyRegistrationItem - 使用 id 字段
private Long id;

// ReviewTaskItem - 同时有 id 和 registrationId
private Long id;
private Long registrationId;

// AdminReviewTaskItem - 同时有 id 和 registrationId  
private Long id;
private Long registrationId;
```

**结论：** 项目中不同DTO使用了不同的字段命名方式，导致前端处理不一致。

## 解决方案

**策略：** 为列表DTO同时提供 `id` 和 `registrationId` 两个字段，值相同，确保前端使用任一字段名都能正常工作。

### 修改1: GroupedRegistrationItem.java

**文件路径：** `src/main/java/com/trae/pinguan/web/dto/GroupedRegistrationItem.java`

**修改内容：**

```java
@Data
@AllArgsConstructor
public class GroupedRegistrationItem {
    @Schema(example = "101", description = "报名ID（与registrationId相同）")
    private Long id;
    @Schema(example = "101", description = "报名ID")
    private Long registrationId;
    @Schema(example = "项目A")
    private String projectName;
    @Schema(example = "某医院")
    private String institutionName;
    @Schema(example = "三级甲等")
    private String institutionLevel;
    @Schema(example = "BASIC")
    private GroupType groupType;
    @Schema(example = "M1")
    private String groupCode;
    
    // 自定义构造函数，确保 id 和 registrationId 值相同
    public GroupedRegistrationItem(Long registrationId, String projectName, String institutionName, 
                                   String institutionLevel, GroupType groupType, String groupCode) {
        this.id = registrationId;
        this.registrationId = registrationId;
        this.projectName = projectName;
        this.institutionName = institutionName;
        this.institutionLevel = institutionLevel;
        this.groupType = groupType;
        this.groupCode = groupCode;
    }
}
```

**关键点：**
1. 添加 `id` 字段
2. 保留 `registrationId` 字段（向后兼容）
3. 自定义构造函数，将同一个值同时赋给两个字段

### 修改2: RegistrationFilterItem.java

**文件路径：** `src/main/java/com/trae/pinguan/web/dto/RegistrationFilterItem.java`

**修改内容：**

```java
@Data
@AllArgsConstructor
public class RegistrationFilterItem {
    private Long id;
    private Long registrationId;
    private String projectName;
    private String institutionName;
    private String institutionLevel;
    private GroupType groupType;
    private String groupCode;
    private LocalDateTime submittedAt;
    private String subjectTypeCode;
    private String methodCode;
    private String subjectTypeLabel;
    private String methodLabel;
    private String applicantName;
    
    // 自定义构造函数，确保 id 和 registrationId 值相同
    public RegistrationFilterItem(Long registrationId, String projectName, String institutionName,
                                  String institutionLevel, GroupType groupType, String groupCode,
                                  LocalDateTime submittedAt, String subjectTypeCode, String methodCode,
                                  String subjectTypeLabel, String methodLabel, String applicantName) {
        this.id = registrationId;
        this.registrationId = registrationId;
        this.projectName = projectName;
        this.institutionName = institutionName;
        this.institutionLevel = institutionLevel;
        this.groupType = groupType;
        this.groupCode = groupCode;
        this.submittedAt = submittedAt;
        this.subjectTypeCode = subjectTypeCode;
        this.methodCode = methodCode;
        this.subjectTypeLabel = subjectTypeLabel;
        this.methodLabel = methodLabel;
        this.applicantName = applicantName;
    }
}
```

**注意事项：**
- `RegistrationFilterItem` 是通过 JPA 的构造函数投影（Constructor Projection）创建的
- Repository 查询中传入的 `r.id` 会被映射到构造函数的 `registrationId` 参数
- 构造函数内部将该值同时赋给 `id` 和 `registrationId`

## 影响范围

- [x] `RegistrationFilterItem.java` - 添加 `id` 字段

- 原本使用 `registrationId` 的代码：正常工作
- 原本使用 `id` 的代码：现在也能正常工作

## 建议

### 前端代码统一

建议前端统一使用 `id` 字段获取报名ID：

```javascript
// 推荐方式 - 使用 id 字段
const registrationId = item.id;

// 也支持（向后兼容）
const registrationId = item.registrationId;

// 最佳实践 - 优先使用 id，回退到 registrationId
const registrationId = item.id || item.registrationId;
```

### 后续规范

对于返回实体列表的DTO，建议统一：
1. 主键字段统一命名为 `id`
2. 如需明确语义，可同时提供 `xxxId` 作为别名
3. 确保前端可以使用统一的字段名访问主键

## 总结

**问题：** 书审分组和面谈分组列表的关键ID字段命名不统一

**原因：** 不同DTO使用了不同的字段命名（有的用 `id`，有的用 `registrationId`）

**解决：** 为分组相关的DTO同时提供 `id` 和 `registrationId` 字段，值相同

**效果：** 
- ✅ 前端可以使用任一字段名获取报名ID
- ✅ 向后兼容，不影响现有功能
- ✅ 统一了API响应格式
- ✅ 解决面谈分组页面点击详情无反应的问题
