# 自动分组算法说明

## 功能概述

自动分组算法用于将竞赛报名项目智能分配到不同的细分组（A1/A2/B1/B2/C1/C2等），实现以下目标：

1. **同机构项目集中**: 同一机构的多个项目尽量集中在1-2个分组，最多不超过3个分组
2. **分组大小均衡**: 每个分组的项目数量保持在20-31个之间，标准差≤2.5
3. **按组别独立处理**: 基层组/综合组/进阶组分别独立分组，互不影响
4. **智能桶数计算**: 根据项目总数自动计算最优分组数量

## 算法设计依据

### 历史数据分析

基于2024-2025年历史数据分析：

| 指标 | 数值 | 说明 |
|------|------|------|
| 机构项目数分布 | 56.7%机构报1-3个项目<br>43.2%机构报4-8个项目 | 大部分机构项目数较少 |
| 组别分布 | 基层组25%<br>综合组65%<br>进阶组10% | 综合组占主导 |
| 多项目负责人 | 1.5%负责人提交多个项目 | 极少数情况 |
| 项目分组特征 | 92.9%分布在2个细分组<br>78.6%在同一大类内 | 优先保持同一大类 |

### 核心约束条件

1. **机构散落限制**
   - 优选: 1-2个分组
   - 可接受: 3个分组
   - 避免: 4个以上分组

2. **分组大小限制**
   - 最小: 20个项目
   - 最大: 31个项目
   - 标准差: ≤2.5

3. **组别独立性**
   - 基层组(A)、综合组(B)、进阶组(C)分别独立处理
   - 不跨组别分配

## 算法流程

### 1. 数据准备

```
1. 获取所有待分组的报名（可按status筛选）
2. 按groupType分组（BASIC/COMPREHENSIVE/ADVANCED）
3. 对每个groupType独立处理
```

### 2. 分组前缀确定

| 组别 | groupType | 前缀 | 示例 |
|------|-----------|------|------|
| 基层组 | BASIC | A | A1, A2, A3... |
| 综合组 | COMPREHENSIVE | B | B1, B2, B3... |
| 进阶组 | ADVANCED | C | C1, C2, C3... |

### 3. 最优分组数计算

```java
目标大小 = (minSize + maxSize) / 2  // 约25-26个项目
初始分组数 = (总项目数 + 目标大小 - 1) / 目标大小

// 确保不超出范围
最小分组数 = (总项目数 + maxSize - 1) / maxSize
最大分组数 = (总项目数 + minSize - 1) / minSize

最终分组数 = max(最小分组数, min(初始分组数, 最大分组数))
```

**示例**:
- 总项目数: 250个
- 目标大小: 25个
- 初始分组数: 250 / 25 = 10个
- 最小分组数: 250 / 31 = 9个
- 最大分组数: 250 / 20 = 13个
- 最终分组数: 10个 ✓

### 4. 机构项目分配策略

#### 4.1 按机构项目数排序

```
机构列表按项目数降序排序（大机构优先分配）
```

#### 4.2 确定机构占用分组数

```java
基于容量 = (机构项目数 + maxSize - 1) / maxSize
基于散落限制 = min(maxSpread, (机构项目数 + minSize - 1) / minSize)

机构占用分组数 = min(基于容量, 基于散落限制)
机构占用分组数 = max(1, min(机构占用分组数, 总分组数))
```

**示例**:
- 机构A有8个项目，maxSize=31，maxSpread=2
  - 基于容量: (8 + 31 - 1) / 31 = 1个分组
  - 基于散落限制: min(2, (8 + 20 - 1) / 20) = min(2, 1) = 1个分组
  - 最终: 1个分组 ✓

- 机构B有50个项目，maxSize=31，maxSpread=2
  - 基于容量: (50 + 31 - 1) / 31 = 2个分组
  - 基于散落限制: min(2, (50 + 20 - 1) / 20) = min(2, 3) = 2个分组
  - 最终: 2个分组 ✓

#### 4.3 分配到最空的桶

```
1. 找到当前负载最小的N个桶（N=机构占用分组数）
2. 将机构的项目均匀分配到这N个桶中
3. 如果有余数，优先分配给前面的桶
```

**示例**:
- 机构C有7个项目，需要2个分组
- 当前桶负载: [20, 22, 21, 23, 24]
- 选择最空的2个桶: 桶0(20个), 桶2(21个)
- 分配: 桶0放4个项目，桶2放3个项目
- 结果: [24, 22, 24, 23, 24]

### 5. 分配group_code

```
对每个桶中的项目分配group_code
桶0 -> A1, 桶1 -> A2, 桶2 -> A3...
```

## 算法特点

### 优点

1. ✅ **智能桶数计算**: 根据项目总数自动计算最优分组数量
2. ✅ **机构项目集中**: 同机构项目优先集中在1-2个分组
3. ✅ **负载均衡**: 使用最小负载优先策略，保持各分组均衡
4. ✅ **组别独立**: 基层组/综合组/进阶组分别独立处理
5. ✅ **参数可配置**: 支持自定义分组大小、散落限制等参数

## 注意事项

1. **权限要求**: 需要OPS或COMMITTEE_ADMIN权限
2. **数据状态**: 建议在报名截止后执行自动分组

4. **手动调整**: 自动分组后可以手动调整个别项目的分组
