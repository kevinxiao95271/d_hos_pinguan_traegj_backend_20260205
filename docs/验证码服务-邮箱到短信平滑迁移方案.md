# 验证码服务：邮箱到短信平滑迁移方案

## 一、架构设计原则

### 核心思想：面向接口编程
通过抽象接口 + 策略模式，实现邮箱和短信的无缝切换，对业务层完全透明。

```
业务层 (AuthService)
    ↓
抽象接口 (VerificationService)
    ↓
具体实现 (EmailVerificationService / SmsVerificationService)
```

## 二、接口设计

### 2.1 抽象接口
```java
public interface VerificationService {
    /**
     * 发送验证码
     * @param recipient 接收者（邮箱或手机号）
     * @param purpose 用途
     * @return 验证码ID
     */
    String sendCode(String recipient, VerificationPurpose purpose);
    
    /**
     * 验证验证码
     * @param recipient 接收者
     * @param code 验证码
     * @param purpose 用途
     * @return 是否验证成功
     */
    boolean verifyCode(String recipient, String code, VerificationPurpose purpose);
    
    /**
     * 检查频率限制
     * @param recipient 接收者
     * @return 是否允许发送
     */
    boolean checkRateLimit(String recipient);
}
```

### 2.2 邮箱实现（Phase 1）
```java
@Service
@Profile("email") // 或通过配置切换
public class EmailVerificationService implements VerificationService {
    
    @Autowired
    private JavaMailSender mailSender;
    
    @Autowired
    private VerificationCodeRepository codeRepository;
    
    @Override
    public String sendCode(String email, VerificationPurpose purpose) {
        // 1. 生成6位验证码
        String code = generateCode();
        
        // 2. 保存到数据库
        VerificationCode entity = VerificationCode.builder()
            .recipient(email)
            .code(code)
            .purpose(purpose)
            .expiresAt(LocalDateTime.now().plusMinutes(5))
            .build();
        codeRepository.save(entity);
        
        // 3. 发送邮件
        sendEmail(email, code, purpose);
        
        return entity.getId().toString();
    }
    
    private void sendEmail(String to, String code, VerificationPurpose purpose) {
        SimpleMailMessage message = new SimpleMailMessage();
        message.setTo(to);
        message.setSubject(getSubject(purpose));
        message.setText(getEmailContent(code, purpose));
        mailSender.send(message);
    }
}
```

### 2.3 短信实现（Phase 2）
```java
@Service
@Profile("sms") // 或通过配置切换
public class SmsVerificationService implements VerificationService {
    
    @Autowired
    private AliyunSmsClient smsClient;
    
    @Autowired
    private VerificationCodeRepository codeRepository;
    
    @Override
    public String sendCode(String phone, VerificationPurpose purpose) {
        // 1. 生成6位验证码
        String code = generateCode();
        
        // 2. 保存到数据库（同样的表结构）
        VerificationCode entity = VerificationCode.builder()
            .recipient(phone)
            .code(code)
            .purpose(purpose)
            .expiresAt(LocalDateTime.now().plusMinutes(5))
            .build();
        codeRepository.save(entity);
        
        // 3. 发送短信
        smsClient.sendSms(phone, getTemplateCode(purpose), code);
        
        return entity.getId().toString();
    }
}
```

## 三、数据库设计（通用）

### 验证码表（邮箱和短信共用）
```sql
CREATE TABLE verification_codes (
    id BIGSERIAL PRIMARY KEY,
    recipient VARCHAR(128) NOT NULL,  -- 邮箱或手机号（通用字段）
    code VARCHAR(6) NOT NULL,
    purpose VARCHAR(32) NOT NULL,     -- REGISTER, LOGIN, RESET_PASSWORD
    is_used BOOLEAN DEFAULT FALSE,
    expires_at TIMESTAMP NOT NULL,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    INDEX idx_recipient_purpose (recipient, purpose),
    INDEX idx_expires_at (expires_at)
);
```

**关键设计**：
- `recipient` 字段长度128，既能存邮箱也能存手机号
- 表名和字段名都是通用的，不包含"sms"或"email"字样
- 业务逻辑完全相同，只是发送渠道不同

### 4.2 动态切换（推荐）
```java
@Configuration
public class VerificationConfig {
    
    @Value("${app.verification.type}")
    private String verificationType;
    
    @Bean
    public VerificationService verificationService(
            EmailVerificationService emailService,
            SmsVerificationService smsService) {
        
        return "sms".equals(verificationType) ? smsService : emailService;
    }
}
```

## 五、业务层调用（完全透明）

```java
@Service
public class AuthService {
    
    @Autowired
    private VerificationService verificationService;  // 自动注入，不关心具体实现
    
    public void sendRegisterCode(String recipient) {
        // 业务层不需要知道是邮箱还是短信
        verificationService.sendCode(recipient, VerificationPurpose.REGISTER);
    }
    
    public boolean register(RegisterRequest request) {
        // 验证验证码
        if (!verificationService.verifyCode(
                request.getRecipient(), 
                request.getCode(), 
                VerificationPurpose.REGISTER)) {
            throw new BusinessException("验证码错误");
        }
        
        // 继续注册流程...
    }
}
```

### 混合模式（可选）
如果需要同时支持邮箱和短信：
```java
@Service
public class HybridVerificationService implements VerificationService {
    
    @Autowired
    private EmailVerificationService emailService;
    
    @Autowired
    private SmsVerificationService smsService;
    
    @Override
    public String sendCode(String recipient, VerificationPurpose purpose) {
        if (recipient.contains("@")) {
            return emailService.sendCode(recipient, purpose);
        } else {
            return smsService.sendCode(recipient, purpose);
        }
    }
}
```

## 十三、总结

### 架构优势
✅ **零迁移成本**：数据库表结构完全兼容  
✅ **代码解耦**：业务层不感知具体实现  
✅ **配置切换**：改1行配置即可切换  
✅ **前端友好**：只需改UI文案  
✅ **可扩展**：未来可支持邮箱+短信双通道  

### 风险评估
⚠️ **邮箱到达率**：可能进垃圾箱（提醒用户检查）  
⚠️ **用户习惯**：医疗行业用户更习惯短信  
⚠️ **邮箱有效性**：部分用户可能没有邮箱  

### 最终建议
**先用邮箱快速验证流程，待短信服务申请完成后一键切换。**

架构设计保证了切换成本几乎为零，是最优方案！
