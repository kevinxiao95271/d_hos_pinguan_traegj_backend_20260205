## 新需求拆解

### 需求1: 决赛分组
**描述**: 决赛先按规则完成项目分组，再为每组匹配对应专家

**业务流程**:
```
1. 从入围名单（面谈入围）获取进入决赛的项目
2. 按规则分组（手动分组 or 自动分组）
   - 按组别分组（基层组、进阶组、综合组）
   - 按分数段分组
   - 按机构区域分组
3. 为每个分组设置组号（如决赛A组、B组、C组）
4. 确认分组结果
```

### 需求2: 专家分配
**描述**: 为每组匹配对应专家

**业务流程**:
```
1. 选择决赛某个分组
2. 从评委池中选择专家
3. 分配专家到该分组（创建评审任务）
4. 约束条件：
   - 专家背景搭配（医疗、护理、管理）
   - 避免同机构专家
   - 专家负载均衡
5. 确认分配结果
```

### 需求3: 现场实时打分
**描述**: 采用系统实时打分，支持扫码打分，同步记录现场打分结果

**业务流程**:
```
1. 生成打分二维码（按项目或按评委任务）
2. 评委扫码进入打分页面
3. 实时提交打分
4. 实时更新排名（可选）
5. 现场大屏展示（可选）
```

### 需求4: 结果汇总
**描述**: 汇总书审、面谈、决赛三项得分，计算项目总得分，根据总得分判定所获奖项

**业务流程**:
```
1. 获取项目的三项得分（书审、面谈、决赛）
2. 按权重计算总得分
   总得分 = 书审得分 × 书审权重% + 面谈得分 × 面谈权重% + 决赛得分 × 决赛权重%
3. 按总得分排名
4. 设置奖项规则：
   - 一等奖：前5%
   - 二等奖：前15%
   - 三等奖：前30%
   - 或按分数段：≥90分一等奖，≥80分二等奖，≥70分三等奖
5. 生成获奖名单
6. 导出获奖证书
```

## 技术考虑

### 1. 扫码打分实现方案
**方案A: Token-based**
- 生成短期有效的token（如30分钟）
- token存储在数据库（qrcode_tokens表）
- 扫码后通过token获取任务信息
- 优点：简单、无状态
- 缺点：需要清理过期token

**方案B: JWT-based**
- 将任务信息编码到JWT中
- 无需存储token
- 优点：完全无状态
- 缺点：无法撤销token

**推荐**: 方案A

---

### 2. 实时打分状态更新
**方案A: 轮询（Polling）**
- 前端每5-10秒请求一次API
- 简单易实现
- 适合现有架构

**方案B: WebSocket**
- 实时推送更新
- 更好的用户体验
- 需要额外的WebSocket支持

**推荐**: 方案A（先实现轮询，后期可升级WebSocket）

---

### 3. 综合成绩计算
**位置**: 服务层（RegistrationService）
- 在服务层实现三项得分汇总
- 支持自定义权重
- 缓存计算结果（如果性能有问题）
