## 支持的查询场景

### 场景1: 书审环节
```http
# 所有书审任务
GET /api/admin/reviews/tasks?competitionId=21&stage=BOOK

# 待确认的书审任务
GET /api/admin/reviews/tasks?competitionId=21&stage=BOOK&status=PENDING

# 已评分的书审任务
GET /api/admin/reviews/tasks?competitionId=21&stage=BOOK&status=SCORED
```

### 场景2: 面谈环节
```http
# 所有面谈任务
GET /api/admin/reviews/tasks?competitionId=21&stage=INTERVIEW

# 待确认的面谈任务
GET /api/admin/reviews/tasks?competitionId=21&stage=INTERVIEW&status=PENDING

# 已评分的面谈任务
GET /api/admin/reviews/tasks?competitionId=21&stage=INTERVIEW&status=SCORED
```

### 场景3: 跨环节查询（新增功能）
```http
# 所有环节的所有任务
GET /api/admin/reviews/tasks?competitionId=21

# 所有环节的待确认任务
GET /api/admin/reviews/tasks?competitionId=21&status=PENDING
```

## 重要发现

### 1. 评审专家分组字段已废弃
- `reviewerGroupCode` 和 `interviewGroupCode` 字段仍然存在但已不使用
- 数据库中这些字段有值（如"A1"），但不影响任务分配
- 评委可以评审任何组别的项目，不受这些字段限制

### 2. 评委分配灵活性
- 同一评委可以评审多个组别的项目
- 同一项目可以分配给多个评委
- 分配主要基于 `expertBackground`（专业背景）字段

### 3. 任务状态流转
```
PENDING（待确认）
    ↓
CONFIRMED（已确认）
    ↓
SCORED（已评分）
    ↓ (可能)
RETURNED（已退回）
```

## 前端对接要点

### 1. 请求头配置
```javascript
headers: {
  "Authorization": `Bearer ${token}`,
  "Content-Type": "application/json"
}
```

### 2. 参数说明
- `competitionId`: 必填，竞赛ID
- `stage`: 可选，不传则查询所有环节
- `status`: 可选，不传则查询所有状态

### 3. 状态显示
建议使用不同颜色标识不同状态：
- PENDING（待确认）：黄色
- CONFIRMED（已确认）：蓝色
- SCORED（已评分）：绿色
- RETURNED（已退回）：红色

### 4. 数据展示建议
- 按环节分组显示（书审/面谈）
- 支持按状态筛选
- 显示评委工作负荷统计
- 支持按组别筛选
