## 功能4：机构报名数量限制

### 功能描述
限制同一机构在同一赛事中的报名项目数量，防止单个机构提交过多项目。

### 业务规则
- **限制对象**：同一机构在同一赛事中
- **限制内容**：报名项目总数不得超过N个
- **默认值**：N = 8
- **可配置**：运维可通过系统设置修改限制值

### 实现内容

#### 1. 报名数量检查
在 `RegistrationService.create()` 方法中添加检查逻辑：
- 查询系统设置获取限制值（默认8）
- 统计该机构在该赛事中已有的报名数量
- 如果已达上限，拒绝创建并返回错误信息

#### 2. 配额查询API
创建 `InstitutionQuotaResponse.java` DTO，提供配额查询接口供前端使用。

**接口：** `GET /api/registrations/institution-quota`

**查询参数：**
- `competitionId` (必填): 赛事ID
- `institutionId` (必填): 机构ID

**响应示例：**
```json
{
  "success": true,
  "data": {
    "institutionId": 1,
    "institutionName": "浙江大学医学院附属第二医院（浙二医院）",
    "competitionId": 21,
    "competitionName": "2026浙江品管大赛",
    "currentCount": 2,
    "maxCount": 8,
    "remainingCount": 6,
    "canRegister": true
  }
}
```

**字段说明：**
- `currentCount`: 当前已报名数量
- `maxCount`: 最大允许报名数量
- `remainingCount`: 剩余可报名数量
- `canRegister`: 是否还可以报名

#### 3. 系统设置管理
**配置键：** `maxRegistrationsPerInstitution`  
**默认值：** 8

**查询接口：** `GET /api/admin/settings?key=maxRegistrationsPerInstitution`

**修改接口：** `POST /api/admin/settings`
```json
{
  "key": "maxRegistrationsPerInstitution",
  "value": "10"
}
```

### 错误提示
```
该机构报名数量已达上限（8个项目），无法继续报名
```

### 测试结果
✅ 测试通过（浙二医院已报名2个，最大8个，剩余6个）
