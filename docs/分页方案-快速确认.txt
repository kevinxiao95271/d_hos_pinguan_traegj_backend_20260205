================================================================================
                           兼容性方案对比
================================================================================

方案A：可选分页参数（推荐）⭐
────────────────────────────────────────────────────────────────────────────
  核心：新增可选参数 page/size，不传则保持原样

  优点：
    ✅ 完全兼容旧代码（无需修改）
    ✅ 前端可渐进式升级
    ✅ 支持全量查询（导出场景）
    
  缺点：
    ⚠️ 响应格式不统一（分页时返回PageResult对象）
    
  示例：
    旧调用: /api/reviews/tasks/stage?competitionId=21&stage=BOOK
    返回: { "data": [ {...}, {...} ] }  ← 数组
    
    新调用: /api/reviews/tasks/stage?competitionId=21&stage=BOOK&page=0&size=20
    返回: { "data": { "content": [...], "totalPages": 8 } }  ← 对象


方案B：始终返回分页格式（不推荐）
────────────────────────────────────────────────────────────────────────────
  核心：所有API统一返回分页格式

  优点：
    ✅ 格式统一
    
  缺点：
    ❌ 破坏兼容性（所有旧代码必须改）
    ❌ 无法全量查询
    ❌ 迁移成本高


方案C：新增独立分页API（折中）
────────────────────────────────────────────────────────────────────────────
  核心：新增 /paged 后缀的API

  优点：
    ✅ 完全兼容旧API
    
  缺点：
    ⚠️ API数量翻倍
    ⚠️ 代码重复


================================================================================
                          推荐实施方案（方案A）
================================================================================

第一阶段：评审任务列表分页
────────────────────────────────────────────────────────────────────────────
  API: GET /api/reviews/tasks/stage
  
  新增参数:
    - page: Integer（可选）- 页码，从0开始，不传则返回全部
    - size: Integer（可选）- 每页数量，默认20
    - sort: String（可选）- 排序，格式: "fieldName,asc/desc"
  
  响应变化:
    不传page → 返回 List<ReviewTaskItem>（兼容旧版）
    传page   → 返回 PageResult<ReviewTaskItem>（新版分页）
  
  改动文件:
    - PageResult.java（新建）
    - ReviewTaskRepository.java（新增分页方法）
    - ReviewService.java（支持分页逻辑）
    - ReviewController.java（新增参数）
  
  开发时间: 1-2小时


第二阶段：报名筛选分页（后续）
────────────────────────────────────────────────────────────────────────────
  API: GET /api/admin/registrations/filter
  
  改动同上

前端改动
────────────────────────────────────────────────────────────────────────────
  - 立即修改: ❌ 否（旧代码可继续使用）
  - 建议迁移: ✅ 是（大数据量页面优先）
  - 改动示例:
  
    // 旧代码（无需修改）
    const tasks = response.data.data;  // 数组
    
    // 新代码
    const pageResult = response.data.data;  // PageResult对象
    const tasks = pageResult.content;
    const total = pageResult.totalElements;


性能提升

    - 前端渲染: 流畅
