# 评审驳回后再次打分 - 机制说明

## 一、问题确认

**问题**：评委打分之后被驳回，还可以再次打分吗？

**答案**：✅ 可以！当前实现完全支持驳回后再次打分。

## 二、技术实现

### 2.1 核心代码逻辑

#### submitScore() 方法
```java
@Transactional
public ReviewScore submitScore(ReviewScoreRequest request) {
    ReviewTask task = reviewTaskRepository.findById(request.getReviewTaskId())
            .orElseThrow(() -> new IllegalArgumentException("评审任务不存在"));
    
    // 关键：使用 findByReviewTaskId().orElse() 模式
    ReviewScore score = reviewScoreRepository.findByReviewTaskId(task.getId())
            .orElse(ReviewScore.builder().reviewTask(task).build());
    
    // 更新评分数据（如果已存在则覆盖）
    score.setPlan(request.getPlan());
    score.setProblem(request.getProblem());
    // ... 其他字段
    score.setTotal(total);
    score.setSubmittedAt(LocalDateTime.now());
    
    ReviewScore saved = reviewScoreRepository.save(score);
    
    // 更新任务状态为 SCORED
    task.setStatus(ReviewStatus.SCORED);
    reviewTaskRepository.save(task);
    
    return saved;
}
```

**关键机制**：
- `findByReviewTaskId().orElse()` 模式
- 如果评分记录已存在 → 获取并更新（覆盖）
- 如果评分记录不存在 → 创建新记录
- 无论哪种情况，最后都保存并将任务状态设为 SCORED

#### updateStatus() 方法
```java
@Transactional
public ReviewTask updateStatus(ReviewTaskStatusRequest request) {
    ReviewTask task = reviewTaskRepository.findById(request.getReviewTaskId())
            .orElseThrow(() -> new IllegalArgumentException("评审任务不存在"));
    
    task.setStatus(request.getStatus());
    return reviewTaskRepository.save(task);
}
```

**功能**：
- 管理员可以直接更新任务状态
- 可以将 SCORED 改为 RETURNED（驳回）

### 2.2 数据库设计

#### review_tasks 表
```sql
CREATE TABLE review_tasks (
    id BIGSERIAL PRIMARY KEY,
    registration_id BIGINT NOT NULL,
    reviewer_id BIGINT NOT NULL,
    stage VARCHAR(32) NOT NULL,
    status VARCHAR(32) NOT NULL,  -- PENDING, CONFIRMED, SCORED, RETURNED
    created_at TIMESTAMP
);
```

#### review_scores 表
```sql
CREATE TABLE review_scores (
    id BIGSERIAL PRIMARY KEY,
    review_task_id BIGINT NOT NULL UNIQUE,  -- 一对一关系
    plan DECIMAL(5,2),
    problem DECIMAL(5,2),
    action DECIMAL(5,2),
    success DECIMAL(5,2),
    review DECIMAL(5,2),
    operation DECIMAL(5,2),
    presentation DECIMAL(5,2),
    total DECIMAL(6,2),
    highlight TEXT,
    weakness TEXT,
    submitted_at TIMESTAMP
);
```

**关键设计**：
- `review_task_id` 是外键且唯一（UNIQUE）
- 一个评审任务只能有一条评分记录
- 再次打分时会更新这条记录，而不是创建新记录

## 三、业务流程

### 完整流程图

```
┌─────────────────────────────────────────────────────────┐
│                     评审打分流程                          │
└─────────────────────────────────────────────────────────┘

1. 第一次打分
   ┌──────────────┐
   │ 评委提交评分  │
   └──────┬───────┘
          │ submitScore()
          ↓
   ┌──────────────────────────┐
   │ 创建 ReviewScore 记录     │
   │ review_task_id = 123     │
   │ total = 70.0             │
   │ highlight = "表现良好"    │
   └──────┬───────────────────┘
          │
          ↓
   ┌──────────────────────────┐
   │ 更新任务状态              │
   │ status: PENDING → SCORED │
   └──────────────────────────┘

2. 管理员驳回
   ┌──────────────┐
   │ 管理员驳回    │
   └──────┬───────┘
          │ updateStatus()
          ↓
   ┌──────────────────────────┐
   │ 更新任务状态              │
   │ status: SCORED → RETURNED│
   └──────────────────────────┘
   
   注意：评分记录仍然存在，只是任务状态变了

3. 第二次打分（修改后重新提交）
   ┌──────────────┐
   │ 评委再次提交  │
   └──────┬───────┘
          │ submitScore()
          ↓
   ┌──────────────────────────┐
   │ 查找已存在的评分记录      │
   │ findByReviewTaskId(123)  │
   └──────┬───────────────────┘
          │ 找到了！
          ↓
   ┌──────────────────────────┐
   │ 更新评分数据（覆盖）      │
   │ total = 91.0             │
   │ highlight = "创新突出"    │
   │ submitted_at = 最新时间   │
   └──────┬───────────────────┘
          │
          ↓
   ┌──────────────────────────┐
   │ 更新任务状态              │
   │ status: RETURNED → SCORED│
   └──────────────────────────┘
```

### 状态流转

```
PENDING/CONFIRMED → SCORED → RETURNED → SCORED → RETURNED → ...
    ↑                ↑         ↑          ↑
    初始状态      第一次打分   驳回    第二次打分
```

## 四、数据特点

### 4.1 评分数据覆盖

| 操作 | review_scores 表 | review_tasks 表 |
|------|-----------------|----------------|
| 第一次打分 | 创建新记录 (id=1) | status = SCORED |
| 管理员驳回 | 记录不变 | status = RETURNED |
| 第二次打分 | 更新记录 (id=1) | status = SCORED |

**关键点**：
- 评分记录的 ID 不变
- 所有字段都会被覆盖
- `submitted_at` 更新为最新提交时间
- 不保留历史版本

## 七、注意事项

### 7.1 当前限制

⚠️ **没有评分历史记录**
- 第二次打分会完全覆盖第一次的数据
- 无法查看第一次打分的内容
- 无法对比两次打分的差异

⚠️ **没有驳回原因记录**
- 数据库中没有存储驳回原因
- 评委不知道为什么被驳回
- 评委不知道应该修改哪些内容

⚠️ **没有驳回次数限制**
- 可以无限次驳回和重新提交
- 没有驳回次数统计

## 九、总结

### 核心机制
✅ **支持驳回后再次打分**  
✅ **使用 findByReviewTaskId().orElse() 模式**  
✅ **评分数据会被覆盖，不保留历史**  
✅ **任务状态正确流转：SCORED → RETURNED → SCORED**  

### 业务特点
- 一个评审任务只有一条评分记录
- 再次打分会更新现有记录，而不是创建新记录
- 评分记录的 ID 不变，只是字段值被更新
- `submitted_at` 会更新为最新提交时间

### 适用场景
- 评委打分有误，需要修改
- 管理员发现评分不合理，要求重新评审
- 评分标准调整，需要重新打分

### 前端对接要点
1. 显示任务状态（RETURNED 时显示"已驳回"）
2. 驳回后加载已有评分数据，方便评委修改
3. 提交接口保持一致，无需区分第一次还是第二次
4. 建议显示驳回原因（需要额外实现）
