# 草稿过滤修复报告

## 📋 问题描述

**问题**：书审分组和面谈分组列表中包含了草稿（DRAFT）状态的报名记录

**影响范围**：
- `/api/admin/registrations/filter` - 筛选列表API（书审和面谈分组使用）
- `/api/admin/registrations/interview-groups` - 面谈分组API

**业务需求**：
- ✅ 只有已提交（SUBMITTED）状态的报名才能进入分组列表
- ❌ 草稿（DRAFT）状态的报名不应该出现在分组列表中

---

## 🔍 问题分析

### 修复前的状态

**数据库统计**：
- 总报名数：129条
- DRAFT（草稿）：62条
- SUBMITTED（已提交）：67条

**API返回情况**（修复前）：
- 筛选列表API：返回 129条（包含草稿 ❌）
- 面谈分组API：返回 129条（包含草稿 ❌）

### 问题根因

#### 问题1：筛选列表API缺少状态过滤

**位置**：`RegistrationRepository.filterRegistrations()`

**问题代码**：
```java
@Query("select new com.trae.pinguan.web.dto.RegistrationFilterItem(...) " +
       "from Registration r " +
       "where r.competition.id = :competitionId " +
       // ❌ 缺少状态过滤条件
       "and (:groupType is null or r.groupType = :groupType) " +
       // ...其他条件
)
```

#### 问题2：分组API缺少状态过滤

**位置**：`RegistrationService.groupByGroupCode()`

**问题代码**：
```java
public List<GroupedRegistrationResponse> groupByGroupCode(Long competitionId) {
    List<Registration> registrations = registrationRepository.findByCompetitionIdWithInstitution(competitionId);
    // ❌ 没有过滤状态，直接处理所有记录
    for (Registration registration : registrations) {
        // ...
    }
}
```

---

## 🛠️ 修复方案

### 修复1：在SQL查询中添加状态过滤

**文件**：`src/main/java/com/trae/pinguan/repository/RegistrationRepository.java`

**修改内容**：
```java
@Query("select new com.trae.pinguan.web.dto.RegistrationFilterItem(...) " +
       "from Registration r " +
       "where r.competition.id = :competitionId " +
       "and r.status = 'SUBMITTED' " +  // ✅ 新增：只查询已提交的报名
       "and (:groupType is null or r.groupType = :groupType) " +
       // ...其他条件
)
```

### 修复2：在分组逻辑中过滤草稿

**文件**：`src/main/java/com/trae/pinguan/service/RegistrationService.java`

**修改内容**：
```java
public List<GroupedRegistrationResponse> groupByGroupCode(Long competitionId) {
    List<Registration> registrations = registrationRepository.findByCompetitionIdWithInstitution(competitionId);
    Map<String, List<Registration>> grouped = new LinkedHashMap<>();
    for (Registration registration : registrations) {
        // ✅ 新增：只处理已提交状态的报名
        if (registration.getStatus() != RegistrationStatus.SUBMITTED) {
            continue;
        }
        // ...后续分组逻辑
    }
}
```

## 🎯 业务影响

### 正面影响

✅ **数据准确性**：
- 分组列表只显示已提交的报名，符合业务需求
- 避免草稿状态的报名被错误地分配给评审专家

✅ **用户体验**：
- 管理员看到的是真实的待评审报名
- 避免评审专家看到未完成的草稿

✅ **数据完整性**：
- 所有已提交的报名都有 `submittedAt` 时间
- 草稿状态的报名 `submittedAt` 为 null 是合理的

---

### 业务逻辑验证

| 状态 | 是否出现在分组列表 | `submittedAt` | 说明 |
|-----|------------------|--------------|-----|
| DRAFT（草稿） | ❌ 否 | null | 用户还在编辑，未提交 |
| SUBMITTED（已提交） | ✅ 是 | 有值 | 已提交，等待评审 |
| RETURNED（退回） | ⚠️ 否（暂不支持） | 有值 | 可能需要后续支持 |
| APPROVED（已审核） | ⚠️ 否（暂不支持） | 有值 | 可能需要后续支持 |

**说明**：当前只过滤 SUBMITTED 状态，如果需要支持 RETURNED 或 APPROVED 状态，可以修改条件为：
```java
and r.status in ('SUBMITTED', 'RETURNED', 'APPROVED')
```
